## D24 — Format upgrades go only through kw_project_upgrade, which Claude Code always asks the user about (amends D21)

*Confidence: high.*

**Choice (resolved 2026-09-24 from ANALYSIS-TOOLING §9 decisions 6-7 and research track 06; amends D21):**

**The tool.** The only way kiwrap converts a user's design files to a newer KiCad format is `kw_project_upgrade(project, from_kicad, to_kicad, files)`.
- It is published with `_meta["anthropic/requiresUserInteraction"]: true` (declared as `ToolSpec.meta`; mcp 2.2 publishes it as `_meta`) and DESTRUCTIVE annotations.
- Its schema has no `dry_run`, no `confirm` and no common `persist` argument, so the user is never asked to approve a call that can only fail.

**What the server does with the arguments.** Under the project lock, the server rebuilds `upgrade_args` with one function. The E_FORMAT_UPGRADE_REQUIRED refusal uses the same function, and it does not depend on which kinds of file the refused write touched.
- `from_kicad` is the project's KiCad line.
- `to_kicad` is the install spec that the tool pins, and the args also carry `to_format {sch, pcb}`. A version prefix or an install root, as kw_env lists it, is accepted. What is compared is the resolved install's formats: every 10.99 nightly and bench build reports the same version string.
- `files` are the design files that move to a newer format.

Any difference is refused with E_BAD_ARGS, and the error carries the true `data.upgrade_args`.

**What the conversion does.**
- It converts exactly `files`, with `kicad-cli sch/pcb upgrade` in the sandboxed ConfigRoot of `to_kicad`, on a copy that keeps relative paths.
- It runs ERC/DRC on the copy before and after (DRC does not save, per D22).
- It replaces only the files that changed, snapshots the project first, pins the target, and drops erc_clean/drc_clean if their error count rose.
- It never touches `.kicad_pro`, `.kicad_prl`, `.kicad_dru`, the lib tables or project libraries. The receipt lists them as `not_converted`.

**The consent record.** The receipt records `consent {gate, via, client {name, version}, entrypoint}`. It does not claim that a human clicked: an Agent SDK host's `canUseTool` can approve these calls. Claude Code clients older than 2.1.199 get E_UNSUPPORTED.

**Changes to `kw_project`.**
- It loses `upgrade`, `confirm` and `dry_run`. A stale `action="upgrade"` gets a teaching E_BAD_ARGS that points at the new tool.
- `status` returns `upgrade_args` whenever a write would need an upgrade.
- The new `upgrade_preview` is a read action: it converts a copy under the storage home and reports the ERC/DRC deltas. It writes nothing in the project.

**Read-only mode (D23).** `kiwrap serve --readonly` does not register the tool, and a call to it there gets E_READONLY with the read-only alternatives.

**The VS Code extension.** Its modal calls `kw_project_upgrade(**error.data.upgrade_args)` for its own server's calls. It gets the arguments from `kw_project status` when it upgrades proactively.

**MCP elicitation.** It stays as the frozen, optional shortcut that §9 decision 7 kept, with no new features. It is sent only when the client declares the capability and `CLAUDE_CODE_ENTRYPOINT != claude-vscode`. An accept runs the same conversion core; a decline or cancel means "no answer".

**No fallback token.** kiwrap mints no consent token or nonce.

**Why:** the claims below were verified on this machine.
- **The prompt is enforced by Claude Code itself.** Sources: the official docs ("Require approval for a specific tool") and static reads of the installed claude.exe 2.1.280 and 2.1.281 bundles.
  - The flag's "ask" comes before the bypassPermissions and allow-rule branches.
  - Auto mode falls back to asking before its classifier runs.
  - No hook can approve a flagged `mcp__` tool.
  - dontAsk and headless sessions turn it into a deny.
  - The panel host sends every other permission request to a card that only a click resolves, with "always allow" suppressed. It auto-allows only claude-in-chrome.
- **Why a token would add nothing.** A local token would be writable by the same agent that could run kicad-cli directly.
- **Why `confirm=true` goes.** It was the model attesting consent to itself.
- **Why elicitation cannot be the gate.** The panel answers every elicitation with decline, and Elicitation hooks can answer one with no human.
- **Why the arguments are rebuilt by one function.** Rebuilding them makes the card show exactly what gets converted. A version string alone cannot pick out a nightly, so the formats are compared.
- **Not yet observed.** The panel card has only been verified statically. The manual E2E (`scripts/e2e_consent.py`) is the run-time check. Under D15 it spends only when the owner runs it.

## D25 — Receipt shape: violation `pos` is KiCad's marker location; one cursor grammar; compact receipts under the client's token gate; atomic changes before 1.0

1. **Violation location.** The violation-level `pos` means *where KiCad marks the violation*. This is the name and meaning of upstream MR !2780 (flat `violations[].pos` / `layer` in drc.v1).
   - DRC `pos` / `layer` come from:
     - kicad-cli's JSON marker fields when present (`pos_source: "kicad"`; the fork now, stock KiCad once !2780 merges);
     - else kiwrap's computed location (`"computed"`: pure Python in `kiwrap.formats.analysis.locate` for track/arc/via/pad pairs now, kiwrap-geom for zones and polygons later);
     - else `null`.
   - DRC `pos` is never copied from an item.
   - ERC keeps `pos = items[0].pos` with `pos_source: "item"`. KiCad places about 29 of 49 ERC markers on an item position, so it is usually near. It is `null` when a violation has no items.
   - `items[].pos` stays each item's own anchor: a footprint origin, a track start, a zone's first corner.
   - `closest_points_mm` comes from Tier B, or from flat `path_start` / `path_end` fields if a KiCad build emits them.

   - The fork carries !2780 verbatim; the §9 8(a) path fields become a flat follow-up commit on top of it.
   - One capability key: `cli.drc_json_marker`, detected by field presence. It replaces the doc-only `cli.drc_json_has_marker_pos`.

2. **Cursors.** One grammar for kw_pcb_get (lanes `i`, `u`), kw_sch_get (`i`, `n`), the kw_pcb_drc report (`v`), kw_pcb_check (`i`) and kw_sch_diff (`c`): `<lane><offset>(.<lane><offset>)*@<ver8>`.
   - `ver8` is `sha256(input files + canonical JSON of the arguments that choose list membership or order)[:8]`.
   - Render-only and delivery arguments are excluded: `cursor`, `limit`, `detail`, `out_path`, `format`, `persist`.
   - kw_pcb_check also hashes `.kicad_pro` / `.kicad_dru`.
   - The DRC `v` lane hashes the stored result's `result_id` plus the report filters, so a re-run on the same board bytes invalidates the cursor. The cursor minted by `action='run'` uses the report's default filters.
   - A changed file, result or query gives `E_STALE` (`cursor_version`). The version covers files on disk, not unsaved live edits.
   - A bare integer means "offset n" only on single-lane tools and is `E_BAD_ARGS` on multi-lane calls.
   - Cursors stay readable. Callers pass them back verbatim.

3. **Serialization and size.** The text body of a successful result is the summary line plus `json.dumps(structured, separators=(",", ":"), ensure_ascii=False, default=str)`. Error results keep their `code` / `why` / `fix` lines, with a compact trailing JSON line.
   - All budgets are measured on compact structuredContent: `rendered_size = len(compact) + 1`.
   - `PAGE_BUDGET_CHARS = 28_000`; `RESULT_CEILING_CHARS = 48_000` for every receipt.
   - An item larger than the page budget has its large arrays replaced by counts and a `truncated` flag, and the full item is available via `out_path`.
   - kw_pcb_drc `run` returns complete counts, the first budgeted page of the stored result and `next_cursor` for `action='report'`.
   - kw_sch_check returns a budget-capped list with `violations_truncated`.
   - Both check tools accept `out_path`: the extension reads the complete list from that file, and no ERC store is added until a filtered ERC re-read is needed.
   - Violation dicts leave out keys whose value is null, false or empty, except `pos`.
   - This saves the model no context in Claude Code: it already sees compact structuredContent. It makes the budget equal what the model sees.

4. **Deprecation policy.** While D19 holds and the version is 0.x:
   - no aliases for renamed or removed receipt fields;
   - server, extension, skill, kw_help and tests change in one commit;
   - persisted receipt-shaped documents carry a schema string that is bumped on shape change, and an unknown schema reads as absent (re-run), never migrated;
   - every breaking change goes under "Unreleased - breaking" in CHANGELOG.md.

   One-minor-release deprecation, with a receipt warning naming the replacement, starts at the first external release.

**Why:**
- **Claude Code is what the model sees through (D13/D18).** Versions 2.1.280/281 give the model `JSON.stringify(structuredContent)` for a successful MCP result and drop the text blocks; for an `isError` result they give the text blocks. Anything estimated at `len/4 > 12,500` tokens (about 50,000 characters) is counted by the API, and above 25,000 tokens it is saved to a file with a 2 KB preview.
- **Measured density.** Compact DRC JSON costs 1.86 characters per token, so a 50k-60k character receipt spills. The video DRC run (53,007 characters) is predicted to spill. The live One-Air-Max run (185,454 characters) did spill.
- **The budget was measuring the wrong thing.** The 40k indent=1 budget and the 60k text truncation applied to the text the model never sees, while structuredContent was unbounded (DRC runs of 53k-259k characters).
- **The old `pos` was redundant and misleading.** It equalled items[0].pos in 1,838 of 1,838 measured violations, cost 6-9% of each violation, and pointed at a track start or a zone corner that lay off the board.
- **The alias protected nobody.** There are no external users (0.0.1, D19), the extension never checks the server version, and nothing does arithmetic on cursors. An alias would only keep the misleading name in front of the model.
- **KiCad already computes the marker location.** Its JSON drops it (rc_item.cpp), and !2780 restores it under `pos`.

## D28 — Stackup sublayers: summed thickness, KiCad's thickness-weighted mean, sublayers kept, one model

*Confidence: high.*

**Choice (resolved on evidence 2026-09-24; ANALYSIS-TOOLING §9.9 first bullet, research track 04 §8.4.1):**

**One model.** kiwrap has one stackup model: `kiwrap.formats.reports.stackup.Stackup` / `StackupLayer`.
- `formats/board.py` drops its own `StackupLayer` and re-exports both classes.
- `DesignRules.stackup` becomes a `Stackup` built by `stackup_from_nodes(setup, layers)`.
- The same function backs `parse_stackup_board`.

**A dielectric slot with several sublayers** (`(layer "dielectric N" (type ..) <sub 0> addsublayer <sub 1> ..)`) reports:
- `thickness_mm`: the sum of all sublayers, summed in integer nm.
- `epsilon_r` and `loss_tangent`: Σhᵢxᵢ/Σhᵢ over the sublayers. If Σh = 0, sublayer 0's values.
- `material`, `color`, `dielectric_type` and `thickness_locked`: sublayer 0's.
- `spec_frequency_hz` and `dielectric_model`: the value all sublayers share, otherwise None.
- `sublayers`: empty for a single-sublayer slot. Otherwise every sublayer top to bottom, each carrying its own thickness, material, εr, tan δ, lock, colour, spec frequency and model, plus the parent's `kind`, `dielectric_type` and `dielectric_id`.
- New `dielectric_id`: the 1-based slot counter. Sources are matched by this id, never by name.
- New `physical_layers()` method: returns `sublayers or (self,)`.
- New board-only `defaulted` (compare=False): the fields filled from KiCad's load defaults.
- `Stackup.raw` becomes compare=False, hash=False.

**The parsers mirror KiCad's load behaviour.**
- A missing token takes KiCad's default. Dielectric sublayer 0: FR4 / 4.5 / 0.02 / 1 GHz / constant. Sublayers 1 and up: no material / 1.0 / 0.0. Solder mask: 3.3 / 0.0.
- `(spec_frequency 0)` becomes None.
- `""` and "Not specified" become None.
- JSON and IPC follow the proto3 rule: a missing scalar is zero, and `DM_UNKNOWN` becomes None.
- The CSV parser reads KiCad's real property labels: "Impedance Controlled", "Plated edges", "EdgeConnector" (value `yes[,bevelled]`).

**kw_pcb_get stackup.**
- `kinds=['stackup']` (review item 11) serialises the model explicitly, not through `rec()`.
- The planner's `stackup` operation gets the board file as its first provider. The CLI JSON and IPC stay as oracles and fallback.
- A board with no `(stackup)` section reports `has_stackup_section=false` and is tagged `stackup_defaulted`.
- The field text states the combination rule and says to use `sublayers` for physics.
- A sublayer with no material, or with εr ≤ 1.0, gets a per-slot note: "KiCad default, slot mean unreliable".

**No change** to `kw_pcb_setup` (it writes no stackup, and the CST preserves `addsublayer`) or to the DSN export (Specctra carries no dielectric data).

**Physics rules for kw_pcb_analyze** are recorded as its spec, not built now:
- Build the bands from `physical_layers()`.
- Substitute FR4 4.5 / 0.02 for any sublayer that was defaulted or has εr ≤ 1.0, tag it `stackup_defaulted`, and say in the receipt that KiCad's own calculator uses 1.0.
- A dielectric tan δ of 0.0 counts as defaulted for loss figures only.
- Tier 0 uses the per-side thickness-weighted εr. It is tagged `estimate`/`mixed_dielectric` when max/min εr on a side exceeds 1.10, and escalates to tier 1 when available.
- Loss comes only from the tier-1 field-energy weighting.
- Apply the Djordjevic-Sarkar correction per sublayer once a real board uses it.

**Why:**
- **Thickness has to be summed.** Every KiCad geometric consumer sums sublayers: board thickness, GetLayerDistance, the 3D viewer, STEP, and the via-stack DRC. The file's own `(general (thickness))` equals the sum on all 6 demo boards with sublayers, and first-sublayer-only fails on them (jetson 1.711 vs 1.501; tinytapeout 1.56252 vs 1.42626). The missing thickness alone is why jetson In2 came out at 39.4 Ω instead of 51.6 Ω.
- **The εr mean is a parity choice, not a physics claim.** In FEM, the arithmetic and series means stay within 0.2 points of each other up to an εr ratio of 1.3, and both beat first-sublayer. The arithmetic mean is the one KiCad's own calculator uses (10.0.6), and it composes along a path. At large εr ratios no single number is right, so physics reads sublayers, not slot means.
- **The locked flag follows KiCad.** KiCad's "Adjust dielectric thickness" treats secondary sublayers as fixed and skips a slot only when sublayer 0 is locked (panel_board_stackup.cpp:512-570).
- **One model and mirrored defaults** make the file, JSON, CSV and IPC sources agree field by field, verified on the 10.99 nightly. They also let the file provider serve KiCad 10.0 (D16 co-primary), where kicad-cli has no stackup export.

**Known KiCad limitations (private drafts only, D19):**
- IPC-2581 writes sublayer 0's thickness and material on every sublayer row.
- ODB++ uses sublayer 0 only.
- The Gerber job file decides whether to write each sublayer's εr/tan δ from sublayer 0.
- The JSON carries only the slot colour.
- The CSV repeats sublayer 0's colour on every sublayer row.

Never use per-row IPC-2581 thickness as an oracle.

## D29 — Fab limits: JLCPCB-only curated data, and a vendor-floor gate that a bare force does not skip

*Confidence: high.*

**Choice (resolved 2026-09-24 on evidence, review decision 9, request item 24):**

**What v1 curates.** JLCPCB only, in `src/kiwrap/data/fab_limits.json` (schema 1, millimetres).
- There are seven sets: `jlcpcb-2layer-{1,2,2.5,3.5,4.5}oz` and `jlcpcb-multilayer-{1,2}oz` (4-32 layers). The 6+ layer differences are conditioned entries.
- Aliases: `jlcpcb-2layer`, `jlcpcb-4layer`, and `jlcpcb` (picks the set automatically).
- Each source records `url`, `read`, `page_updated` (null when the page has no date) and a note. Each vendor also lists `related_pages`. For JLC these are the capabilities page and the HDI FAQ (page_updated 2026-09-07), which is recorded as a source but not curated as a set.
- Each limit records:
  - `abs`: the lowest number the vendor states, which is the reject threshold;
  - `min`: the standard floor, which is the warning threshold;
  - optionally `rec` with `rec_kind` (cost or yield);
  - `on_min` (reject or degrade), `src`, `row`, a verbatim `quote`, and optionally `note`, `when`, `conflicts` and `checked_by`.
- A row that the same page contradicts (thickness 4.5 vs 3.2, the blind/buried row vs the FAQ, heavy copper) carries `conflicts` and is never reject-class.
- The OSH Park draft moves to `tests/` as a fixture vendor. It proves inheritance, `when` conditions and selection. v1 adds no `fab_limits` argument to `kw_fab_export`; the vendor comes from `profile='jlcpcb'`.

**Refresh.** `scripts/dev/refresh_fab_limits.py` is stdlib-only and run by hand.
- It fetches every source and related page into `Platform.temp_dir` and normalises the text (cells joined by ` | `, NBSP turned into a space, whitespace collapsed).
- It checks every quote and `page_updated`, and lists links on index pages that are not yet known.
- It exits 1 on drift and never edits values. `--stamp` re-dates only sources with no drift.
- Run it before each release, when the oldest read date is more than 180 days old, and after any DFM rejection.
- At runtime, data read more than 365 days ago adds degraded `fab_limits_stale` and a warning. The gate outcome does not change.
- CI checks the file's structure only, offline.

**Gate.** `kw_fab_export` evaluates a `fab_limits` gate whenever the profile names a vendor and the targets include drill, odb, ipc2581, or gerbers with a copper layer. It is not a stage.

It blocks with `E_FAB_LIMIT` in three cases:
- A board covered by a curated set breaks the vendor's stated absolute floor for its layer class:
  - track, arc, copper-graphic stroke, copper-text stroke or zone min_thickness width below the 1 oz `abs` (JLC 2-layer 0.10, multilayer 0.0762);
  - a via or PTH drill below 0.15.
- The board breaks a vendor-wide row: layer count outside 1-32, or an outline beyond the extended maximum or minimum, checked in both orientations.
- The stored DRC result for the current board sha256 holds error-severity `clearance` or `shorting_items` violations whose actual gap cannot be measured yet (finding `clearance_violations_unmeasured`, until review item 18's parser lands).

Everything else is a warning (`degrade`, `cost` or `uncovered`) and never blocks:
- the selected copper weight's standard floor, or the 0.09 floor with its BGA fan-out note;
- rings, hole spacing, hole-to-copper, SMD pad gaps, slots, NPTH, edge, mask and silk;
- order-form parameters (copper weight, thickness, finish, mask colour), which only select the set: stackup copper rounds up to the next weight offered, and 1 oz is used when no stackup is found (degraded `stackup_defaulted`);
- blind, buried or micro vias, which no v1 set covers. These give degraded `fab_limits_uncovered` ("needs JLC HDI service") and turn all geometric findings except vendor-wide rows into warnings.

**Clearance evidence.** Clearance is `proven` only when all of these hold:
- the stored DRC's `board_sha256` and `rules_sha256` match the current files;
- clearance and shorting_items run at error severity;
- there are no clearance exclusions and the result has zero copper errors;
- the resolved minimum is at or above the floor. The resolved minimum is taken over netclass clearances, custom-rule mins (not floored), and pad, footprint and zone local overrides (floored at the board minimum), with net ties excluded.

Otherwise clearance is `unverified`, which is a warning, or it is the blocking case above.

**Force.** `force={'reason': ..., 'gates': ['drc_clean', 'fab_limits']}` overrides only the gates it names.
- A bare force overrides only `drc_clean`, as it does today.
- The gate is always evaluated and its findings are always reported.
- A forced gate is logged only if it would have blocked. The snapshot says `(forced drc_clean+fab_limits: <reason>)`. `data.forced` stays the reason string and `data.forced_gates` is added.
- In D23 read-only mode the record lives in the receipt only.
- `dry_run` keeps its flat `data.gate` and adds `data.gates.fab_limits`.

**Why:**
- Evidence settles the reject class. JLC started selling HDI on 2026-09-07, while its capability table still says "don't support Blind/Buried". JLC 2-layer offers 2.5, 3.5 and 4.5 oz, with extended sizes of 1020x600 and 1016x596. The stock vme-wren demo has 0.018 mm outer copper. Any of these, treated as a reject, would block buildable boards.
- The real floors bite on real boards. The stock jetson-agx-thor demo has 3258 through-vias drilled at 0.1 mm, below JLC's 0.15 mm, and is correctly blocked. Every other stock demo passes the etch and drill floors.
- Without the stored-violation rule, item 24's forced-DRC 0.044 mm gap would ship. It ships in v1 only when force names `fab_limits`.
- JLC is D9's vendor and the only vendor in the requests. A second vendor would need a new tool argument. The fixture proves the schema without refresh upkeep.

**Correction to review T3:** for the item-24 audit copy, an appended unconditional rule does override earlier custom rules, because the engine iterates forward and the last match wins. Local overrides, however, return before any custom rule and are floored only by the board minimums. So the copy must:
- put the fab rules last;
- raise the board minimums to the fab floors;
- clear local clearance overrides, or filter results by the parsed actual value.

## D30 — native.geom is an environment record in kiwrap.analysis; six import contracts; a content-keyed board-model cache in core

*Confidence: high.*

**Choice (resolver, 2026-09-24, settles ANALYSIS-TOOLING §9 decisions 5, 9b and 9c and review themes T5 and T8, on measured evidence):**

**(a) Environment capability.** `native.geom` is a fact about the Python environment, not about a KiCad install, so `capability.py` and its disk cache stay as they are.
- `kiwrap.analysis.environment.probe_environment(environ=None) -> EnvCapabilities` returns a read-only Mapping with `.has()`.
- Keys:
  - `native.geom`
  - `native.geom_version`
  - `native.geom_protocol`
  - `native.geom_reason`: `not_installed`, `import_failed`, `protocol_mismatch`, `built_with_panic_abort`, `disabled` (KIWRAP_GEOM=pure), `restart_required` or `panicked`.

- `native.geom` is true only when the wheel imports, `PROTOCOL` matches, and `PANIC_STRATEGY == "unwind"`.
- The only place that imports `kiwrap_geom` is `kiwrap.analysis.engines.native.load_module()`.
- The probe catches BaseException except KeyboardInterrupt and SystemExit.
- Caching is per process: Services caches the record, and `kw_env(refresh=true)` re-probes. The states `panicked` and `restart_required` are sticky until the process restarts.
- `kw_env` reports the record as `data.environment`.
- Receipts:
  - `data.engine = {geom: native|pure, geom_version, fields}`.
  - Degraded tags: `native_geom_unavailable` and `native_geom_failed`.
- `select_engine()` is the only reader of the key.

**(b) Import rules.**
- `include_external_packages = true`.
- `formats-zero-dep` also lists the runtime third-party packages, including anyio and uvicorn.
- `backends-no-core` is unchanged.
- `layers`: core, backends, sandbox, capability, installation, `platform | analysis`, formats.
- `compute-only-in-analysis`: a forbidden contract on the root package `kiwrap` for kiwrap_geom, numpy, scipy, skfem and shapely. It ignores kiwrap.analysis's own edges and sets `unmatched_ignore_imports_alerting = "none"`.
- `analysis-only-from-core`: backends, sandbox, capability, installation, platform and formats must not import analysis.
- `analysis-no-runtime-deps`: analysis must not import mcp, pydantic and the other runtime packages.
- Ruff TID253 bans module-level imports of the five compute packages.
- Two tests close the gaps that neither tool can see:
  - a subprocess sys.modules leak test, for importlib strings and module-level `try: import`;
  - a grimp allowlist test: formats may import only the stdlib, and analysis only the stdlib plus the five packages.
- The `protected` contract type is not used: it stops the whole run when a listed package is not imported anywhere.
- The block lands in the same change as the analysis skeleton, because a layer that does not exist fails the run.

**(c) Board-model cache.**
- Owner and binding: `kiwrap.core.state.model_cache.ModelCache`. `Services.real()` wraps `file_read_board` with it; hand-built Services are unchanged. Analysis holds no state.
- Key: `(kind, normcase(resolved path), sha256(board bytes), sha256(.kicad_pro bytes or b""))`.
  - The bytes are read once and hashed (42 ms on jetson).
  - On a miss, those same bytes are parsed through a new stdlib-only `BoardFile.from_bytes(data, path, pro_bytes)`.
- One digest per path: admitting a new digest for a path evicts the older one.
- There are no invalidation hooks in `_finish` or in the D23 guard.
- Never cached: paths under `storage_home` or `Platform.temp_dir`.
- Budget:
  - `KIWRAP_MODEL_CACHE_MB` defaults to min(3072, 20 % of physical RAM); kiwrap.platform provides the RAM figure. 0 disables the cache.
  - Entry size is estimated at 25 × the file size. LRU entries are evicted until the estimate fits, before the load starts.
  - At most 8 entries. Idle TTL `KIWRAP_MODEL_CACHE_IDLE_S` = 300. Loads are single-flight.
- Release: every model the wrapper serves carries a `weakref.finalize(board, enqueue_release, board.root)`. A releaser thread then runs `BoardFile.release_steps()`, which clears CST `parent` pointers in slices of 200k nodes.
- GC:
  - After a model estimated at 256 MB or more is admitted: `gc.collect(1)`, then `gc.freeze()`.
  - After its release: `gc.unfreeze()`, and refreeze while other large entries remain.
  - kiwrap never calls a full `gc.collect()`.
- Rule: model sub-objects (Footprint, Pad, Track, ArcTrack, Via, Zone, Graphic and any Node) never outlive the tool call or job that obtained them, and never enter any cache.
- Phasing:
  - The derived per-layer copper namespace and the `Memo` protocol ship with `kw_pcb_analyze`.
  - `board.ipc11` caching is a follow-up. It is keyed on `install.key()` plus the sha256 of the bytes the pooled headless server opened. A bound GUI session is never cached.
- Result staleness (E_STALE) stays content-based and independent of the cache.

**(d) Facade.** `kiwrap.analysis.engine` defines `GeometryEngine` with `supports(op)` over the zero-dependency columnar types in `kiwrap.formats.geometry.copper`, `PureEngine`, `NativeEngine`, `NativeRequired` and `NativeFailure`.
- Refused without the wheel: union, difference, offset and intersection with a non-convex clip. The pure kit has no general boolean. These map to E_UNSUPPORTED `{capability: "native.geom"}`.
- The check happens before the board is loaded. If only some of the requested checks need the wheel, those go in `data.refused` and the rest run.
- Run pure and tagged `native_geom_unavailable`: stroke, unfracture, index, pairs_within, nearest, contains, islands, contacts and rasterize.
- Raster ops run pure in windows of at most 4 Mpx and are tagged `raster_fallback`.
- A native panic re-runs the op pure where a fallback exists, tags `native_geom_failed`, and makes `panicked` sticky for the process.

**Why:**
- Environment record:
  - Nothing in the install-keyed capability cache changes when the wheel is added or removed.
  - Analysis of a file model runs without KiCad.
  - Only a real import proves that the .pyd loads, and it costs 2-4 ms.
- Contracts: every contract was run on copies of the working tree. The six contracts gave 6 kept on the clean tree and broke on the violating trees as intended. `protected` stops the run when a listed package is absent from the graph.
- Content key:
  - A stat key fails on local NTFS: 171 of 200 same-size rewrites kept identical `(mtime_ns, size, ino)`.
  - A `_finish` hook would discard boards loaded correctly after a write inside the mutation (pcb_route_auto.py:1211, and the validators).
- Release and GC:
  - A jetson model holds 2.1 GB (25× its file size).
  - Dropping it without clearing the parent pointers stalled the automatic GC for 8.4 s on 3.14.4. A resident model caused pauses of 4.2 s on 3.12 and 0.9 s on 3.14. With freeze, the worst pause was 21 ms on 3.14 and 0.63 s on 3.12.
  - `sys.getrefcount` cannot see a caller that holds only node-bearing sub-objects.
  - BoardFile is a plain dataclass with no back-references, so a finalize callback fires as soon as the last holder drops it.

## D31 — kiwrap-geom ships as a committed abi3 wheel pinned by uv.lock in a default dependency group, built with a panic=unwind pyext profile

*Confidence: high.*

**Choice (resolved on evidence, 2026-09-24, from ANALYSIS-TOOLING section 9 decisions 1 and 9 and research track 05 section 7).**

**Delivery.** The pyo3 extension `kiwrap-geom` is delivered to the checkout as one tracked file: `helper/kiwrap-geom/wheel/kiwrap_geom-<v>-cp311-abi3-win_amd64.whl`, with `*.whl binary` in `.gitattributes`. The root `pyproject.toml` declares it in a default dependency group rather than in `[project].dependencies` or an extra:

```toml
[dependency-groups]
native = ["kiwrap-geom==<v> ; sys_platform == 'win32' and platform_machine == 'AMD64'"]

[tool.uv]
default-groups = ["dev", "native"]

[tool.uv.sources]
kiwrap-geom = { path = "helper/kiwrap-geom/wheel/kiwrap_geom-<v>-cp311-abi3-win_amd64.whl" }
```

- **Pin.** `uv.lock` records the relative path and the sha256. It is the only version and hash pin: no engines.json entry, no bootstrap download, no VSIX copy and no extension change.
- **How it reaches the servers.** Both servers start with a plain `uv run --project <checkout>`: the extension's server and the one Claude Code starts from `.mcp.json`. That command installs the wheel on a fresh clone and updates it after `git pull`, from any working directory. Neither Rust nor network access is needed.
- **When to wire it.** The dependency is added only in the commit where `kiwrap.analysis` first imports `kiwrap_geom`. Until then the crate is developed with `cargo test -p kiwrap-geom`.

**Cargo.** In `helper/Cargo.toml`:

- `members = ["kiwrap-live", "kiwrap-geom"]` and `default-members = ["kiwrap-live"]`;
- a new `[profile.pyext]` with `inherits = "release"` and `panic = "unwind"`;
- `[profile.release]` stays `panic = "abort"` for `kiwrap-live`.

In the crate's `pyproject.toml`: `[tool.maturin] profile = "pyext"`, `editable-profile = "dev"`, `[tool.maturin.sbom] rust = false`, and `license-files = ["LICENSE", "THIRD-PARTY.txt"]`.

The module exports:

- `__version__`;
- `PANIC_STRATEGY`, from `cfg!(panic = "unwind")`;
- `SOURCE_FINGERPRINT`, from `option_env!`;
- `PanicException`;
- `_panic_probe()`.

**Build script.** `scripts/build_geom_wheel.py` is stdlib-only and is the single writer of the wheel and of every pin site. It runs in this order:

1. `cargo metadata --locked`.
2. Compute the fingerprint: sha256 over the crate's `Cargo.toml`, `pyproject.toml` and `src/**` with CRLF normalised to LF, plus the parsed `pyext`/`release` profile tables and the `Cargo.lock` closure of kiwrap-geom.
3. `uvx maturin@1.15.0 build --locked`, with `CARGO_ENCODED_RUSTFLAGS` set to `/Brepro` plus `--remap-path-prefix` for cargo home, rustup home and the checkout, and `SOURCE_DATE_EPOCH=315532800`.
4. Check the result in a throwaway venv: it imports and reports `unwind`.
5. Swap in the wheel and update the pins: the group pin, the source path, `GEOM_VERSION` and `GEOM_FINGERPRINT`.
6. `uv lock --upgrade-package kiwrap-geom`, which works offline.

If any step fails, the script restores every file it changed.

**Gates.**

- **`--check`, blocking on every OS.** It verifies:
  - that exactly one wheel exists;
  - that its version agrees across `Cargo.toml`, the group pin, the source path, the `uv.lock` entry and `GEOM_VERSION`;
  - that the wheel's sha256 equals the `uv.lock` hash;
  - that the tree fingerprint's hex string appears inside the committed `.pyd`.

  It runs in two places: from `tests/test_native_wheel.py`, and as a step in the ubuntu `scripts-lint` job, which has no `needs`.
- **Windows-only tests.** They import the wheel, check that `PANIC_STRATEGY` is `unwind`, and check that `_panic_probe()` raises `PanicException` while the interpreter survives.
- **The `geom` job.** It is new and runs on hosted `windows-latest` (D14), filtered to changes under `helper/**` and the build script, with no dependency on `kicad-python-wheel`. It runs `cargo test`, `clippy --profile pyext` and an informational rebuild with a sha comparison, then uploads the artefact.

**Runtime.** `native.geom` is true only when:

- the module imports;
- `__version__ == GEOM_VERSION`;
- `SOURCE_FINGERPRINT == GEOM_FINGERPRINT`;
- `PANIC_STRATEGY == "unwind"`.

Otherwise it reports one of the reasons `missing`, `version_mismatch`, `fingerprint_mismatch` or `abort_build`. The pure fallback runs where one exists; where none exists, the call returns the teaching error from decision 2(a) with the fix "run `uv sync` in the kiwrap checkout".

**Panics.** `PanicException` derives from `BaseException`, so:

- the `kiwrap.analysis` facade converts it into its own error;
- `JobManager._run` (`core/state/jobs.py`) also catches `BaseException`, re-raising `KeyboardInterrupt` and `SystemExit`, as `_base.py:377` already does.

**Python.** Only the GIL build `cp311-abi3-win_amd64` ships, built with pyo3 `abi3-py311`. There is no `.python-version` file, no cp314t or abi3t wheel, and no `free_threaded` runtime reason. Revisit abi3t (PEP 803) when `requires-python` reaches 3.15.

**Why.**

- **Where the wheel has to be.** The wheel's consumer is the checkout venv that both plain `uv run` servers use, so the checkout's lock is the only carrier that reaches both.
- **Why commit it.** Every uv spelling needs the wheel, or its directory, to exist before the first `uv run`. A missing path source or find-links directory fails with "Failed to generate package metadata". The one spelling that tolerates a missing wheel, an explicit flat index, loses the hash and writes an absolute path that fails `--locked` elsewhere. On top of that, the private repo has no anonymous download URL and its origin uses SSH. A download at bootstrap time would therefore stop the server on a fresh clone.
- **Why a default group rather than an extra.** An extra is missing on a fresh clone, goes stale after a bump, and a plain `uv sync` removes it.
- **Why a default group rather than `[project].dependencies`.** A project dependency would put an unindexed `Requires-Dist` back into the built kiwrap wheel, the pattern that reviewer finding 6 removed for kicad-python. A default group behaves the same for every route kiwrap uses and leaves `METADATA` clean.
- **Why the pyext profile.** Cargo rejects `panic` in a per-package profile. With `abort`, a panic kills Python with 0xC0000409; with `unwind` it raises `PanicException`, including from rayon workers.
- **Why the gate is not in the `unit` job.** CI's `unit` and `lint` jobs are skipped while `kicad-python-wheel` fails, and `main` is unprotected. The blocking gate therefore runs in local pytest and in `scripts-lint`.
- **Why normalise line endings.** With `core.autocrlf=true`, the owner's working tree has CRLF files that CI checks out as LF. A raw-byte fingerprint would fail in CI on a wheel the owner built correctly.

**Consequences.**

- **This supersedes** ANALYSIS-TOOLING §4.4 (the `native` extra), §4.5 (a wheelhouse, bootstrap or VSIX delivery) and the §3.7 wording.
- **Unchanged:** `bootstrap.ps1` (its `uv sync --all-extras` installs the default group), `engines.json` (D11 stays for third-party engines), `build_extension.ps1`, the extension, `.mcp.json` and the CI `helper` job.
- **History growth.** Every commit that changes kiwrap-geom sources must carry its rebuilt wheel (about 0.45 MB compressed), so Rust work should be batched into few commits.
- **Merge conflicts.** A conflict in the `.whl` or in `uv.lock` is resolved by rerunning the build script.
- **New dependencies:**
  - `kiwrap-geom`, our own MIT package, on win_amd64;
  - maturin 1.15.0, run through `uvx`, as a build tool;
  - cargo-about, if it is used to generate `THIRD-PARTY.txt`.
