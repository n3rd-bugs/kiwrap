- **[high, VERIFIED LOCALLY]** Every mature KiCad MCP server converged on the SAME three-channel architecture, and they say KiCad forces it: (1) schematics = direct .kicad_sch S-expression editing (no KiCad process), (2) PCB = IPC API (protobuf over NNG, KiCad GUI must be running) or SWIG pcbnew headless as fallback, (3) ERC/DRC/exports = kicad-cli subprocess. Konnect's README: 'Schematic editing: direct .kicad_sch S-expression editing with atomic writes (no KiCad required) | PCB editing: KiCad 10 IPC API | Exports & checks: kicad-cli'. nevenfo: 'Schematic IPC is empty on KiCad 10 — schematic_commands.proto declares no commands — so the S-expression engine is the only path that exists, not a workaround.' kicad-mcp-layer: 'file: Lossless edits of .kicad_sch and .kicad_pro — Schematics, which KiCad 10 exposes no API for.'
  - Evidence: README texts in scratchpad/prior-art/readmes/mixelpixx_Konnect.md, nevenfo_kicad-agentic-mcp.md, ShamanAndrey_kicad-mcp-layer.md. Locally confirmed the schematic IPC gap: kicad-python 0.8.0's kipy/proto/schematic/schematic_commands_pb2.py has zero message types (see experiment 'kipy protos').

- **[high]** Konnect's 'native KiCad plugin' is NOT an in-process integration: it is a PCM package containing (a) a thin SWIG ActionPlugin (plugin/__init__.py) that adds a Tools-menu item and launches/stops the external Rust MCP binary, (b) an api.v1 plugin.json with runtime 'exec' (the IPC-era plugin registration) and (c) an OPT-IN 'native Specctra bridge' (plugin/native_bridge.py): a ThreadingHTTPServer on loopback with a bearer token, run inside pcbnew's Python, exposing POST /v1/export-specctra-dsn which calls pcbnew.ExportSpecctraDSN on the LIVE board — because neither the KiCad 10 IPC API nor kicad-cli can export Specctra DSN. Konnect explicitly labels this bridge 'not the KiCad 11 integration path' (SWIG disappears in 11) and defaults to its own Rust DSN exporter. This is the single best-documented instance of the 'in-KiCad plugin <-> external agent' channel: used only to reach a GUI-only function, authenticated, opt-in, and treated as temporary.

- **[high]** Konnect (successor of KiCAD-MCP-Server) documents exactly why the SWIG-subprocess architecture failed: 'a single tool call travels through TypeScript, schema validation, a spawned Python subprocess, JSON over stdin/stdout, a command router, and finally SWIG-generated C++ proxy objects', 'a zone-fill call that can segfault the backend, proxy-object comparison bugs, and a fallback path that can silently swap backends mid-session', dependency surface 'Node.js + npm tree, Python + pip, wxPython, kicad-skip, KiCad SWIG bindings'. ## Capabilities

- Reuse the proven three-channel split (file-level schematic engine / IPC for the live board / kicad-cli for ERC-DRC-exports) — every serious project independently arrived at it and it is version-tolerant by construction.
- Reuse rjwalters/kicad-tools (MIT) as an immediately usable, version-tolerant parser for .kicad_sch/.kicad_pcb 7-10 plus Specctra DSN export / SES import, a pure-Python DRC pre-check, a placement optimizer and a fallback autorouter (verified parsing identical across 7/8/9/10 locally).
- Reuse kicad-skip (LGPL-2.1) as a lossless generic S-expression editor for schematics if a tiny dependency is acceptable (0 tokens lost on 7-10 sch files); or copy its approach (generic s-expr tree, not dataclasses) into our own MIT engine.
- Reuse atopile/kicadcliwrapper's idea (or the package itself, MIT): generate strongly-typed kicad-cli bindings from `kicad-cli --help` of the detected install, which makes CLI drift 7->10 (no drc/erc in 7, gerber removed in 10, new 3dpdf/stats/upgrade) a data problem instead of code.
- Reuse the official kicad-python (kipy) for board IPC on KiCad 9/10 (board/editor/project commands import and connect fine; only board_jobs is broken in 0.8.0) — and vendor/pin the wheel per KiCad version the way KiPilot and atopile do.
- Reuse KiCanvas (MIT) or Huaqiu's ecad-viewer fork (MIT) as the VS Code webview renderer for schematic/PCB, exactly as KiCad Studio Kit, KiCode and kicanvas-viewer do; use kicad-cli SVG/PNG render as the guaranteed-correct fallback (LukasLang.kicad-viewer approach).
- Reuse VS Code's native `mcpServerDefinitionProviders` + `languageModelTools` contribution points (as KiCad Studio Kit does) so Copilot agent mode, Claude Code (.mcp.json), Cursor and Codex all see the same tool surface without per-client config.
- Reuse Freerouting (GPL, external process) via DSN/SES — and its built-in MCP server since 2.2.4 — for autorouting; reuse Konnect/kicad-tools/kicad-mcp-pro's SES-import logic patterns for headless import.
- Reuse the operational patterns from kicad-mcp-pro / nevenfo / kicad-mcp-layer: capability-parity matrix per KiCad version, read-only default profile, dry-run + mutation gate, editor-lock refusal, IPC commits = one undo step, KiCad-decides-success (ERC/DRC verdict), on-demand toolsets to keep tools/list under ~2K tokens.
- Reuse KiBot (AGPL, run as an external CLI) for CI-grade fabrication packages and variants when the user wants more than kicad-cli exports.
- Reuse PCBWorld's action schema (net select / start route / make line / net end scored by DRC) as the model for a routing tool surface, even if the PNS engine itself is out of reach without a source build.
- Use the KiCad 10 api.v1 plugin manifest ('exec'/'python' runtime, scopes pcb/schematic/footprint/symbol/project_manager) to add a toolbar button in any editor that launches or pings our VS Code-side server — a zero-C++ 'in-KiCad plugin' that works on 9 and 10.

## Limitations

- No prior art achieves schematic editing through KiCad itself on 7-10: KiCad 10's schematic IPC handler is empty (verified in kipy 0.8.0), so all schematic authoring in every project is file-based S-expression writing (or a patched KiCad: Huaqiu 'KiCad CPP SDK', KiPilot on a kicad-master source build).
- Interactive push-and-shove routing, length tuning/meanders and freehand symbol drawing have no IPC/CLI/SWIG surface in any version; PCBWorld had to fork KiCad 9.0.8 source and pybind11 the PNS router (GPLv3). An in-KiCad plugin does NOT unlock these either — only a source patch does.
- Specctra DSN export is GUI/SWIG-only (no kicad-cli subcommand in 7-10; not in IPC 9/10); SWIG pcbnew disappears in KiCad 11 (deprecated since 9.0), so projects that lean on it (Konnect's native bridge, ProductOfAmerica autoroute, IBOM, KiBot) are all on a clock.
- Headless SWIG is unreliable on Windows in 9/10: WriteDRCReport hangs on wx asserts (9.0.5, 10.0.0); API names drift (EDA_UNITS_MILLIMETRES vs EDA_UNITS_MM); SaveBoard writes sidecar project files; Konnect reports zone-fill segfaults.
- The popular Python schematic libraries are unsafe: kicad-sch-api 0.5.6 empties lib_symbols (72 ERC errors, 0 components in netlist after round-trip); kiutils drops hide/exclude_from_sim/etc. and cannot parse KiCad 10 boards; kicad-skip cannot parse 8/9/10 boards; all three are unmaintained or slow-moving (kiutils/kicad-skip last commits 2024).
- kicad-python 0.8.0 on PyPI cannot import board_jobs (broken generated protos); export/plot jobs over IPC are KiCad 11 features anyway.
- Older KiCad cannot read newer files (kicad-cli 8/9 refuse 20260206/20260306-stamped files), so a wrapper that writes 'latest format' silently breaks users on KiCad 8/9; kicad-cli 7 has no ERC/DRC/render at all.
- Freerouting needs Java 21+ (current builds target Java 25); the machine has only Java 17 — routing tests could not be run here.
- atopile 0.15.9 requires Python 3.14 and its Windows wheel crashed with STATUS_ILLEGAL_INSTRUCTION on this AVX-512-less Core Ultra 9 285K, so its KiCad output could not be inspected locally.
- KiCanvas is alpha with known KiCad 9/10 rendering gaps (tables, colors, some files fail to load); Studio Kit tells users to 'Open in KiCad' as source of truth.
- Licensing: Konnect/nevenfo are AGPL-3.0 (commercial license needed for products), KiBot/easyeda2kicad AGPL, Freerouting GPL (fine as a separate process), PCBWorld-Engine GPLv3 (any KiCad-source-derived plugin/binding is GPL). Seeed's server and Finerestaurant have no license file.
- A pcbnew.exe (PID 74560) not started by this task was running on the machine; the only interaction was one read-only kipy get_version call. No GUI was launched by this task and %APPDATA%/kicad was never touched.

## Recommendations

- ADOPT the three-channel architecture (lossless file engine for schematics + IPC for live board on 9/10 + kicad-cli for checks/exports), with SWIG as a strictly optional, sandboxed, timeout-guarded adapter for the two things only it can do headlessly on 7-10 (Specctra DSN export, zone fill) — mirror ProductOfAmerica's 'pcbnew only reads, substrate splices results back' rule.
- BUILD our own lossless concrete-syntax-tree S-expression engine (or vendor kicad-skip's generic approach) with round-trip tests that assert (1) token-multiset equality, (2) kicad-cli ERC/DRC violation-set equality and (3) netlist equality on the 7/8/9/10 demo corpus — the exact test that exposed kicad-sch-api and kiutils corruption here. Do NOT depend on kiutils or kicad-sch-api for writes.
- REUSE rjwalters/kicad-tools (MIT) as an early accelerator for parsing, DSN/SES, placement scoring and a fallback router, but keep it behind our own tool interface so it can be swapped.
- REUSE kicadcliwrapper's generate-from-`--help` technique to build a per-install kicad-cli capability map at first run (cache keyed by `kicad-cli version`), and expose a `capabilities` tool (like kicad-mcp-pro's kicad_capability_parity / Konnect's get_installation_info) so agents know what the installed KiCad can do.
- REUSE the official kicad-python for board IPC, vendoring a pinned wheel per KiCad major inside our server (KiPilot/atopile pattern) and adding a proto-drift check (Konnect #616 idea); implement discovery of the Windows named pipe rather than deriving it from env.
- ON THE 'in-KiCad plugin <-> VS Code extension' CHANNEL: adopt it only in the thin form prior art proved useful — an api.v1 'exec'/'python' plugin (9/10) that adds a toolbar button and hands the current project/document to our VS Code-side server, plus (optionally, 7-10 only, opt-in, token-authenticated loopback like Konnect's native_bridge.py) a SWIG-side helper for Specctra export/zone fill on the LIVE board. Do NOT design core functionality around an in-KiCad plugin: it gets no more API than IPC/SWIG (no schematic API, no PNS router), SWIG dies in KiCad 11, and it must be re-shipped through PCM per major. The 'plugin' buys UX (button, live refresh, dirty-state), not capability.
- ON THE SOURCE BUILD: it is NOT required for anything in scope on installed 7-10 binaries; the only proven reasons prior art built KiCad from source are (a) exposing the push-and-shove router (PCBWorld-Engine, GPLv3 pybind11 patch on 9.0.8), (b) getting the KiCad-11 schematic IPC early (KiPilot), (c) vendor-private schematic SDKs (Huaqiu). Recommend a source build only later, as a debugging aid and to prototype against KiCad 11's schematic IPC/api-server — never as a runtime dependency of the shipped wrapper.
- DESIGN the tool surface for context economy from day one: 15-25 domain-router tools (blwfish: 17 tools, 12 routers) or Konnect/nevenfo-style starter kit + on-demand toolsets + a describe/invoke gateway; never a flat 100-200-tool list.
- MAKE KiCad the judge: every mutating tool returns kicad-cli ERC/DRC deltas and a read-back diff (nevenfo/kicad-mcp-layer pattern), with snapshot/rollback, editor-lock refusal for files KiCad has open, and IPC commits as single undo steps.
- PACKAGE routing as an external, swappable engine: Freerouting via DSN/SES (bundle/download a Java 21+ runtime or use its MCP server), with kicad-tools' router as a no-Java fallback; expose PCBWorld-style primitive route actions (net select / start / segment / end scored by DRC) so LLM agents can also route incrementally.
- SHIP the VS Code extension with: KiCanvas (or Huaqiu ecad-viewer) webview custom editors plus kicad-cli SVG fallback and an 'Open in KiCad' escape hatch; TextMate grammars for .kicad_* and .kicad_dru; Problems-view ERC/DRC; `mcpServerDefinitionProviders` + `languageModelTools` so Copilot/Claude Code/Cursor/Codex all get the same tools; a KiCad-install picker that lists all installed majors (this machine has 7.0/8.0/9.0/10.0 side by side) and writes files in the selected install's format.
- AVOID the recorded mistakes: single-major hardcoding, SWIG-in-subprocess as the primary path, silent-lossy parsers, flat giant tool lists, unpinned kicad-python wheels, assuming Freerouting/Java, model-judged success, and Windows traps (Controlled Folder Access -> set KICAD_DOCUMENTS_HOME; CREATE_NO_WINDOW for children spawned from pcbnew).
- LICENSE strategy: keep the wrapper MIT/Apache; consume Konnect/nevenfo (AGPL), KiBot (AGPL), Freerouting (GPL) only as separate processes or as design references; do not copy code from them.
