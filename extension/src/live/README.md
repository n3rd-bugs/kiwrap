# Live KiCad module (`extension/src/live`, `extension/media/live`)

The "Live KiCad" tabs of the kiwrap VS Code extension: a `*.kicad_pcb` / `*.kicad_sch` opened with the
custom editor `kiwrap.live` shows the matching KiCad editor window streamed by the `kiwrap-live.exe`
helper (docs/DISPLAY.md 7 and 12.6: capture-only view first, hidden KiCad on builds carrying
`mr/display-input`, mirror as opt-in). Other KiCad windows (3D viewer, footprint / symbol editors) open
as `kiwrap.live.panel` WebviewPanels.

## Pieces

| file | role |
|---|---|
| `index.ts` | `activateLive(context, { client?, output?, mediaRoot? }): LiveApi` -- registers the custom editor, panels, commands (`kiwrap.live.open` / `attach` / `openSurface` / `close` / `status` / `raise` / `screenshot` / `forwardKey`) and the shield context keys |
| `liveSession.ts` | `LiveSessionManager`: one session per window -> `kw_live launch` (through ext-core's client) -> `HelperProcess` -> `ControlClient` -> `SurfacesModel`; ends when KiCad's pid dies, the helper reports `process_exit`, or `close()`; `kw_live detach` on close |
| `helperProcess.ts` | owns `kiwrap-live.exe --pid <pid> --listen 127.0.0.1:0 --inject none\|mirror\|hybrid\|events [--cloak-expected] [--fit-to-view] [--allow-any-process]` (the helper mints the token and reports it in the hello line; `--token` only through `extraArgs` for tests), parses the `{port, token, version}` stdout line, restarts on exit (bounded backoff, while the session is wanted), graceful stop (stdin EOF, which the helper honours, then kill, then `taskkill /T`) |
| `controlClient.ts` | `/control` WebSocket (extension host, global `WebSocket` of Node >= 22): `surfaces` / `screenshot` / `raise` / `keyframe` requests with `id` correlation, `hello` + `event` pushes |
| `surfaces.ts` | surface kind -> tab shape (pcb/sch = custom editor, everything else = panel), file -> kind / project dir, `SurfacesModel`, wire normalisation (`rect_px: [l,t,r,b]` -> `{x,y,w,h}`) |
| `webviewHost.ts` | `LiveView`: one webview bound to a surface selector (kind + file, or a fixed id); page html + CSP, host<->page messages, clipboard bridge (`vscode.env.clipboard`), test hooks |
| `liveEditor.ts` / `livePanel.ts` | `CustomReadonlyEditorProvider` (`kiwrap.live`, priority `option`) and the panel registry (`kiwrap.live.panel`, quick pick, optional auto-open of the 3D viewer) |
| `keybindings.ts` + `chords.ts` | keybinding shield: 176 chords + Ctrl+Shift+P / F1 rebound to `kiwrap.live.forwardKey` while a Live tab is active, guarded by `kiwrap.live.shield` (setting `shieldKeys`) and `kiwrap.live.shieldPalette` (setting `keepCommandPalette`, default keeps the palette for VS Code) |
| `mode.ts` / `kwLive.ts` / `kiwrapClient.ts` | inject-mode decision (auto = events on a patched install else view; mirror only on request), `kw_live` wrapper + result unwrapping (MCP result, ext-core `Receipt`, plain object), client resolution (injected object -> command `kiwrap.core.callTool` -> unavailable) |
| `contributes.live.json` | generated by `tools/gen_contributes.mjs`: commands, custom editor, menus, settings, keybindings. `--merge` folds it into `extension/package.json`; `--check` verifies it is current |
| `../../media/live/` | the webview client: `live.html` / `live.css` / `live.js` (DOM glue) and `protocol.js` (pure: frame header, DPI-exact mapping, input serialisation, stats; unit-tested with `node --test`) |

## Integration (ext-core) - done (2026-09-20)

`extension.ts` calls `activateLive(context, { client: { callTool }, output })` with the core MCP client
and mirrors `sessions.onDidChange` / `surfaces.onChange` into the core model (tree, status bar);
`package.json` carries the merged contributions (`gen_contributes.mjs --merge`, `--check` in CI);
`kiwrap.openLive` / `kiwrap.closeLive` delegate to `kiwrap.live.open` / `kiwrap.live.close` and pass
`kiwrap.kicadInstall` as `target_kicad`; after the helper's hello the session registers it with
`kw_live attach`; the mode decision reads kiwrap's `mode_used` / `cloaked`. The list below is kept as
the record of what the wiring consists of.

1. In `extension.ts`: `import { activateLive } from './live'; const live = activateLive(context, { client: { callTool: (n, a) => mcp.call(n, a) }, output });`
   `client.callTool` may return the MCP `CallToolResult`, ext-core's `Receipt`, or the bare payload.
   Without a client the module looks for the command `kiwrap.core.callTool(name, args)`; failing that,
   `kiwrap.live.open` reports "kiwrap core client is not available" and `kiwrap.live.attach` (pid) still works.
2. `node src/live/tools/gen_contributes.mjs --merge` (idempotent) adds the contributions and activation events
   to `package.json`. The esbuild bundle of `src/extension.ts` picks the module up; `media/live/**` must ship in
   the VSIX (no build step).
3. Ship `bin/kiwrap-live.exe` (MIT helper) or let users set `kiwrap.live.helperPath`; a dev checkout also finds
   `../helper/target/{release,debug}/kiwrap-live.exe`.
4. The shared contract is `src/shared/types.ts` (helper protocol, `kw_live` shapes, webview messages).

## Webview client behaviour

Stream: `ws://127.0.0.1:<port>/stream?surface=<id>&token=<t>`; binary frames `[u32 frame_id][u16 w][u16 h]` +
JPEG/WebP (sniffed) decoded with `createImageBitmap`, drop-to-latest while decoding; `meta` text frames set the
size (dirty rects accepted as `[x,y,w,h]` or objects). Layout keeps 1 surface px = 1 device px when it fits
(`kiwrap.live.fit`), otherwise scales down; pointer coordinates go through the canvas bounding rect, so VS Code
zoom and OS scaling cancel out exactly. Input (mirror / hidden modes only): pointer move/down/up with capture
(middle-drag pans), wheel with the Windows sign, key down/up with `code`/`key`/`{ctrl,shift,alt,meta}`, focus,
release-all on blur, optional pointer lock (`kiwrap.live.pointerLock`), a `resize` hint and `clipboard` text
(Ctrl+V hands the VS Code clipboard to the helper first; `meta.clipboard` from the helper lands in
`vscode.env.clipboard`). In view-only mode a click asks the helper to raise the real window. A hidden tab closes
its stream after `hiddenCloseDelayMs` and reconnects on reveal (a quick switch keeps the socket and sends
`keyframe`). HUD: surface, mode, connection, size/scale, fps, kbit/s, input-to-frame latency, Raise / pointer
lock / collapse buttons.

## Contract notes (deviations and assumptions the integrator should know)

- `modifiers` is sent as `{ctrl, shift, alt, meta}` (the helper also accepts a bitmask ctrl=1 shift=2 alt=4 meta=8).
- Extra stream events beyond the contract: `keyframe` (supported by kiwrap-live), `resize` (hint; may be ignored),
  `clipboard` (text; a same-machine helper can ignore it because the OS clipboard is shared).
- The "mirror" preference runs the helper's `hybrid` injector by default (`kiwrap.live.mirrorInjector`), because
  DISPLAY.md 12.6 retires SendInput as a product mode; `--inject mirror` remains selectable.
- The session's input mode is decided from `kw_live`'s result: `mode: 'hidden'` or
  `install.capabilities['gui.input_from_events'] === true` => `--inject events --cloak-expected`.
- kw_live is called as `{action, project, editor, mode}` / `{action, project, session_id}`.
